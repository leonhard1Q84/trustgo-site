# 预订流程：可直接填写的测试输入与预期输出

核对日期：2026-10-28。本表回答“具体输入什么，页面应该显示什么”。全部依据当前内部适配和表单逻辑。现已补齐可通过具体日期／测试卡号触发的本地场景；沿用现有表单、提示和弹层，不增加页面控件。内部付款不发生真实扣款，也不是支付平台测试环境。

## 1. 先用这几组数据

| 要看什么 | 具体输入 | 当前预期输出 |
| --- | --- | --- |
| 查无订单 | 确认号 `TG-QA-NOT-FOUND`，姓氏 `Traveler` | 查单表单提示“未找到匹配的預訂，請確認預訂確認號與姓氏後重試。”；接口 `404 / booking_not_found`，不进入整页 404 |
| 搜索有车 | 开发预览输入 `LAX`，点击机场候选；取车选门店当地今天起第 4 天，还车选取车后第 3 天；年龄 `30`，驾照签发国 `US` | 当前内部数据返回 6 条门店报价、4 个车型组 |
| 搜索无车 | 同一地点，取车改为明天，还车晚于取车；其他参数不变 | 近期取车无库存，0 条报价、0 个车型组 |
| 付款成功 | 普通数字卡号随便填，例如 `1234`；安全码填 `1`，有效期选未来月份，姓名非空并勾选协议 | 本地付款成功，不需要记长卡号或校验码 |
| 付款拒绝 | 卡号只填 `0002`，其他必填完整并勾选协议 | 显示“付款遭拒，請嘗試其他卡片。”；订单仍待付款，可换普通数字重试 |
| 付款卡号校验失败 | 卡号全部填 `0`，其他必填有效 | 收银台提示“請檢查卡號與安全碼。”，不发送付款请求 |

日期为门店当地时间，测试随当前时间滚动，无需维护固定年份和售罄日期。未来不足 72 小时取车无库存；提前至少 72 小时取车有库存。人工测试用“明天”和“4 天后”即可避开边界，不需要记特殊日期。

入口：[中文查单入口](http://localhost:4000/zh/manage-booking/lookup)；当前兼容地址会打开首页上的现有查单弹层，填表步骤相同。每个用例单独提交，避免无意触发每来源每分钟 10 次的查单限流。

| --- | --- | --- | --- | --- |

| O05 | 用下节公共资料实际创建一笔预订；复制创建结果中的确认号 | `Traveler` | 验证通过；从失权订单／结算页带安全 returnTo 进入时恢复原页，否则进入会话列表 | `200`，返回该笔已授权预订 |

`TG-QA-NOT-FOUND` 不符合当前 `TG-年份-随机十六进制` 的生成格式，可稳定用作不存在的测试确认号。成功订单的确认号由当前服务实例实际创建，不能把文档里任意编一个固定号当作可查询的成功订单。

直接访问 [不存在的订单详情](http://localhost:4000/zh/booking/TG-QA-NOT-FOUND) 会转重新验证；直接访问 [不存在的车型](http://localhost:4000/zh/rent/does-not-exist) 才是整页 404。二者不是同一输出。

### 本地故障输入与整页检修画面

使用 `npm run preview` 或 `npm run dev` 启动开发服务后，O08–O11 默认生效，确认号不区分大小写，姓氏填写非空测试值 `Traveler`。这四个保留确认号只选择故障，不对应真实订单，不创建订单、不授予查单权限，也不改变任何真实订单的付款／取消状态。普通奇怪确认号仍按 O01／O02 处理。

| 想看到的画面 | 直接打开 | 当前结果 |
| --- | --- | --- |
| 订单详情首屏服务故障 | [订单检修页](http://localhost:4000/zh/booking/TG-QA-SERVICE-503) | 现有整页检修插图、重试及首页操作，不需要先创建订单或取得访客授权 |
| 收银台首屏服务故障 | [收银台检修页](http://localhost:4000/zh/checkout/TG-QA-SERVICE-503) | 同一错误边界的检修画面；不显示付款表单或订单资料 |
| 上游超时导致首屏失败 | [订单超时检修页](http://localhost:4000/zh/booking/TG-QA-TIMEOUT-504) | 现有通用异常页；没有独立 504 画面 |
| 查单操作服务故障 | [查单表单](http://localhost:4000/zh/manage-booking/lookup) 填 O08–O11 | 留在表单显示对应错误，不进入整页检修 |

仅 `NODE_ENV=development / test` 启用；production 即使设置 `TRUSTGO_RENTAL_MODE=local` 也不启用。设置服务端环境变量 `TRUSTGO_LOCAL_FAULTS=off` 后通过项目预览入口重启，可关闭这些固定故障。生产及关闭后的保留号恢复为普通不存在订单，不返回合成故障；默认生产禁用内部适配的保护仍单独适用。

固定故障会持续触发，同一测试地址点重试仍失败是预期结果；查单可以改填真实已创建的测试订单验证恢复。整页用例可离开该地址回有效页面。开发模式若出现 Next.js 错误覆盖层，关闭覆盖层后检查现有业务错误边界；生产构建不提供这些测试入口。真实请求限流检查仍先于故障选择，短时间大量测试可能让 O08／O10／O11 也先返回实际 429，需等待 60 秒窗口恢复。

O10 不制造真实等待／断网，O11 不制造浏览器断连。实际网络中断和 15 秒客户端超时仍按[异常恢复说明](exception-pages-and-recovery.md)用 Network 工具或测试代理验证；没有在表单中增加故障开关或测试标识。

## 3. 搜索输入 → 输出

### 从首页地点输入开始

开发预览打开 [首页](http://localhost:4000/zh)，输入 `LAX`／`lax`／`Los Angeles`／`洛杉磯`／`洛杉矶`，选择“洛杉磯國際機場 (LAX)”候选，再设置 S01 日期、年龄和驾照签发国后搜索。必须点击候选以取得地点 ID，单纯填写文字不代表已选择地点。候选的 `poiId=poi-lax-airport`、关联门店 `US-LAX-01`，机场搜索应涵盖两家 LAX 门店。

LAX 为已有内部报价的开发测试地点，现已接通首页、结果页及移动端共用的地点搜索和最近选择；美国／洛杉矶浏览项也仅在非 production 环境提供。production 地点选择器保持已有正式目的地配置，不因本地测试数据新增美国运营目的地或索引页面。本节全部 LAX 用例请通过 `npm run preview`／`npm run dev` 的开发服务执行。

搜索当前通过页面服务端逻辑执行，没有一条可照抄为 FE 响应的独立搜索 API。S05–S07 在领域层为 `invalid_search/400`，页面捕获后显示现有提示；不要据此断言浏览器页面本身一定返回 HTTP 400。

所有内部报价统一按滚动规则处理：先将门店当地取车时间解析为真实时刻，再与服务端当前时间比较；提前不足 72 小时无库存，提前至少 72 小时正常返回该地点已有报价。边界按连续 72 小时计算，不按浏览器时区或跨过几个日期计算，夏令时也不改变阈值。原先固定年份的全量／部分售罄区间已移除。

搜索、费率详情和创建预订都使用同一校验，每次查询重新计算；即使报价尚未过期，取车进入近期窗口后也不能创建预订。过去时间仍是校验失败，不能当成正常无车。实际库存、占位和容量由 FE 提供；本规则只用于当前内部测试数据，不是正式渠道的提前预订政策。

四位异常号只有完整输入该四位时才触发，不按普通卡号末四位匹配。原来的六组完整异常卡号仍兼容：`4000000000000002 / 4000000000009995 / 4000000000003063 / 4000002500003155 / 4000000000000119 / 4000000000000259`，按上表顺序对应相同结果。

宽松校验和四位短号只在非 production 环境启用。production 仍检查 15–19 位数字、Luhn、3–4 位 CVC、未来有效期及非空持卡人；默认生产禁用内部付款保护保持有效，不把本地成功当成真实银行卡可用。邮箱由原来的浏览器邮箱校验处理，协议仍需主动勾选。

表单只在内存中校验并将卡号映射成非敏感场景值。付款 API 只接收场景与幂等键，不接收完整卡号、CVC、有效期或持卡人，例如：

```text
POST /api/rental/bookings/实际确认号/payment
{"idempotencyKey":"当前付款意图的UUID","localPaymentScenario":"declined"}
```

`localPaymentScenario` 允许 `success / declined / insufficient_funds / authentication_failed / processing / unknown / unavailable`；省略时沿用成功结果，其他值返回 `400 / invalid_request`。全部仍受服务端授权、订单状态、付款期限和生产环境保护约束。production 默认拒绝内部预订／支付；只有显式配置 `TRUSTGO_RENTAL_MODE=local` 的内部环境才能使用。

P07／P08／P10／P13 明确失败后，本次金额保持 0、订单付款期限不变，换卡会建立新的付款意图；同一幂等键重放失败不会变成成功，同键更换场景会被拒绝。P11／P12 未取得终态前不能重付或取消；本地服务端在付款发起 10 秒后、下一次查单时确认收款，前端不凭倒计时自行判定成功。相同付款不会重复累计金额或产生第二笔交易号。

P10 覆盖的是认证失败结果反馈，没有真实 3DS 挑战窗口、跳转或验签；P12 覆盖付款结果不确定后的查询恢复，不是人为让网络真正超时。表单校验失败可以用 P03／P04／P06 验证。真实支付 provider、3DS 交互、网关超时、验签和回调补偿仍需外部测试环境。
