# 演示部署服务错误 hotfix 验证

## 原因与修复

账号接口原先在 `NODE_ENV=production` 时无条件返回 503；费率与查单的内部适配器也默认拒绝生产构建。Vercel 使用生产构建，因而演示链路被保护开关拦截。截图与此行为一致，尚未取得线上响应或运行日志来排除其他故障。

新增服务端 `TRUSTGO_DEMO_MODE=true` 开关，由 `vercel.json` 为本仓库的演示部署显式设置。账号、验证码、租车适配器使用同一开关；不改写 `NODE_ENV`，未启用演示开关的正式环境继续拒绝内部适配。账号及通知状态在同一进程的路由模块间复用，验证码显示使用现有五语言文案。

此配置只在重新部署后生效。正式接单前必须移除 `vercel.json` 中的演示配置并接入正式服务。

## 已知限制

共享快照只服务演示 / 验收，不能作为正式 FE、账户或支付服务替代。个人验收记录最长保留七天，物理清理随后续业务变更提交；Preview / Production 隔离。高并发或大数据量需正式事务存储；共享快照限制 8 MiB，条件写最多尝试十二次，重试受十二秒总预算限制，故障返回服务错误。

## 后续：跨函数报价丢失与过期提示

线上 HTTP 复现确认：费率页与驾驶人页返回 200，但创建预订返回 `410 rate_expired`。报价在页面函数内存中，建单 API 的独立函数读取不到。原有三分钟期限及客户端设备时钟比较也可能提前触发过期提示。之前的页面状态检查没有验证完整建单链路。

改用私有 Vercel Blob 服务端共享快照，ETag 条件写与重试保证并发幂等；账号、授权、报价、订单、通知及限流状态均纳入同一请求事务。失败付款和限流变更也必须保存，存储错误不得降级为空内存。演示报价设为 30 分钟，搜索、费率、驾驶人页均按服务端时钟与浏览器单调计时计算剩余期限，刷新原报价不续期。

新增 `npm run test:demo-deployment`：每个页面 / API 请求使用独立 Node 进程，覆盖报价到驾驶人、并发建单与付款幂等、结算 SSR 归属、访客授权撤销、账号会话、存储故障、服务端过期、设备时钟偏差和个人数据清理。线上完整 HTTP 链路及最终检查结果将在部署后记录；以上 PC / H5 点击项仍待人工确认。

最终本地检查：跨进程演示回归 10 项、账号 33 项、预订恢复 26 项、租车业务 53 项、本地场景 21 项全部通过；build、TypeScript、i18n 与最终 HTML 检查通过；lint 为 0 errors / 66 条既有 warnings。

实际 Blob 集成检查发现下载经 Brotli 压缩后返回 `W/` 弱 ETag，而条件写入需要原对象 ETag；已规范化版本标识，并让隔离回归模拟该真实响应。修正后，使用真实 Blob 的 API 处理器检查返回 200，原先为 `DEMO_STORAGE_BUSY` / 503。线上全链路仍需随后验证。

## 2026-11-17：结算页并发冲突修复

线上函数日志确认，截图对应的结算页在 Blob 条件写入时抛出 `The conditional request cannot succeed due to a conflicting operation against this resource.`，digest 为 `3117245913`。订单仍存在；同时段的账号会话和待付款入口也出现 503。此前仅重试 `BlobPreconditionFailedError`，没有覆盖 Blob 以 `bad_request` 返回的并发操作冲突；GET 轮询还会为限流计数和过期清理写回整个共享快照。

| 调整 | 结果 |
| --- | --- |
| 结算 / 订单、驾驶人、管理入口 SSR 与账号会话、待付款 / 访客订单轮询只读 | 读取最新私有快照，不因清理或派生状态参与写锁竞争；业务变更仍事务提交 |
| 读查询计数 | GET 使用实例内预算，敏感 POST 登录 / 查单 / 付款等保留共享限流；无授权读取依然拒绝 |
| 事务重试 | 覆盖两类条件写冲突、短暂读 / 写网络故障和服务不可用，遵守 rate-limit 的等待时间；最多十二次且预算十二秒，单次存储 I/O 最多四秒 |
| SDK 重试 | `VERCEL_BLOB_RETRIES=0`，避免 SDK 与事务重试叠加，耗尽前端十五秒超时 |
| 过期清理 | 记录到期立即不可读取，物理删除随下一次业务变更保存；不为过期清理让每个页面写回 |
| 日志 | 只记录读 / 写阶段、错误类别和尝试次数，不记录确认号、Cookie、快照或个人资料 |
