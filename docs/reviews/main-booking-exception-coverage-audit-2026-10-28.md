## 1. 结论

**TrustGo 已有主要预订规则保护，但还没有达到 IX 当前异常分支和恢复体验的覆盖广度；两者也都不能视作真实交易全链路已经验收。**

| 判断 | 证据与边界 |
| --- | --- |
| 主干不是空壳 | 有服务端费率上下文、HttpOnly 订单授权、幂等、重叠预订检查、支付期限、在线实付基数、取消试算及版本核对 |
| 404 与异常分类不完整 | 费率过期落通用异常；订单／收银台把服务不可用吞成 404；查单把网络错误和限流显示成未找到 |
| 存在额外业务缺陷 | 地点文字缺少 ID 时详情补成 LAX；过去日期搜索仍有结果；费率有效但取车时间已过仍可创建订单 |

## 2. 什么时候是 404，什么时候是异常

必须分开看“HTTP/API 错误码”“页面状态”和“用户下一步”。`RentalError.status = 410/404` 本身不会让服务端页面自动返回对应页面：只有 Route Handler 显式写入响应，或页面调用 Next.js `notFound()`，才进入对应处理。发生流式输出时，外层 HTTP 状态还可能与页面状态不同，本审查不把源码分支等同于实测 HTTP 状态。

| 场景 | 应有行为 | TrustGo 当前行为 | 判定 |
| --- | --- | --- | --- |
| 不存在的公共路径、文章、市场／城市／门店组合 | 404，提供有效导航 | 对应页面调用 `notFound()` | 分类基本正确；最终 HTTP／多语言待人工与 HTTP 验证 |
| 无语言前缀或不支持的首段 | 按现有语言路由策略跳转，最终不存在再 404 | middleware 307 加语言前缀；不是所有非法首段立即 404 | 需覆盖重定向目标与循环边界 |
| 未知车辆路径且无有效 offer | 404 | `!existingId && !offerId` 调用 `notFound()` | 有实现 |
| 路径车辆与有效费率车辆不符 | 404 或明确无效链接 | `vehicle.id !== vehicleId` 调用 `notFound()` | 有实现 |
| 显式 offer 已不可用／不属于搜索 | 费率不可用状态，返回原结果或重搜 | `createRateDetails()` 抛 `RentalError('rate_unavailable', 404)`，页面没有分流，进入通用异常 | 缺业务恢复 |
| 费率 ID 不存在、3 分钟过期、进程重启丢失 | 费率已失效，保留可恢复行程并重新查询 | 详情／驾驶人服务端读取直接抛 `rate_expired`，进入通用异常；点击“重试”仍使用失效 ID | 明确缺漏 |
| 驾驶人页不带费率 ID | 返回搜索，或上下文缺失提示 | redirect 到 `/{lang}/rent` | 有兜底，但无原行程解释 |
| equipment 参数损坏／越界 | 无效选择提示／安全重置，允许恢复 | 详情和驾驶人页直接 `notFound()` | 把业务输入错误归为 404 |
| 日期、时间、年龄、签发国无效 | 搜索表单校验，保留可修正内容 | 服务端 `validateSearch()` 抛错，结果／详情无专用捕获 | 通用异常代替表单反馈 |
| 无库存、未覆盖目的地、不支持的异地组合 | 正常空结果；允许修改搜索 | 结果页展示空结果 | 分类正确；不应改成 404 |
| 筛选后无匹配 | 正常筛选空态，清除筛选 | 已有独立空态和清除操作 | 已实现 |
| 未知订单／不属于当前授权范围 | API 可统一 404 避免泄露；页面提供重新验证入口 | API 统一 `booking_not_found/404`；订单和收银台页面直接 404，只能回首页 | 授权保护正确，恢复体验不足 |
| 姓氏不匹配 | 留在查单表单，统一验证失败信息 | API 返回 404；表单显示未找到 | 可接受的防枚举口径 |
| 会话过期、Cookie 丢失、另一设备打开已有订单 | 请求重新验证或登录，不泄露订单 | SSR 直接 404；已打开页面轮询错误被静默忽略 | 缺少恢复与失效处理 |
| 查单超时／断网／503／429 | 临时失败或稍后再试，保留输入 | 查单卡全部显示未找到；订单列表全部切到 missing | 错误分类缺漏 |
| 下单冲突／幂等体变更 | 原页提示，查看已有订单／继续可恢复订单 | `booking_conflict/submission_changed` 已有反馈与链接 | 已实现，页面交互待确认 |
| 支付期限到／已取消／已支付／处理中／未知 | 各自明确状态与下一步；未知不重付 | `canPayBooking()` 会阻止支付，但收银台仍主要显示表单与倒计时，缺独立结果与恢复面板 | 防护有，体验未闭合 |
| 服务不可用、未配置生产适配 | 503 或服务异常，提供可重试入口 | API 503；订单／收银台 `catch { notFound(); }` 把同一原因转成 404 | 明确误分类 |
| 非预期渲染错误 | 通用异常页；根布局错误用全局兜底 | 有 `[lang]/error.tsx` 与 `global-error.tsx` | 有兜底；全局兜底仍硬编码英文 |

主要证据：`src/app/[lang]/rent/[id]/page.tsx:38`、`:53`、`:64`；`src/app/[lang]/book/driver/page.tsx:30`；`src/app/[lang]/booking/[confirmationCode]/page.tsx:23`；`src/app/[lang]/checkout/[reservationId]/page.tsx:23`；`src/integrations/fleetedge/local-rental-adapter.ts:40`、`:96`、`:124`；`src/app/api/rental/[...action]/route.ts:55`。

| 评价／邀请 | 当前主链未见同等实现 | customer-review 资格／邀请／提交模块及测试 | 属订后范围差距，需确认是否纳入 TrustGo 业务范围 |
| 在线身份核验 | 上传／审核未接入，提交禁用；但展示仍承诺可预上传和跳柜台 | IX 有相关入口和模块，也需逐项确认真实后端能力 | TrustGo 不可算完成；当前也不应对所有订单无条件展示可办理 |
| 在线修改／续租 | 业务规则不开放，查单／账户文案仍宣传 | IX 代码／文案不是 TrustGo 业务授权 | 应修正文案，不应据此新增修改或续租功能 |

## 5. 必须覆盖的回归用例矩阵

状态标记：**自动**＝现有测试明确执行；**部分**＝规则有但页面／恢复或完整边界未覆盖；**缺失**＝本次发现缺口；**外部**＝须接入真实 FE／支付／通知后验证。所有行的 PC／H5 页面操作仍待人工确认。
