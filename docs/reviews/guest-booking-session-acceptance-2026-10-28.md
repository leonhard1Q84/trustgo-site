# 全局访客查单弹窗验收记录

日期：2026-10-28。浏览器交互、PC / H5 及多语言视觉验收均待人工确认。

## 当前行为

| 场景 | 结果 |
| --- | --- |
| 全站入口 | 导航、页脚及帮助页共用全局查单弹窗；已有访客授权时进入订单列表；首次查单留在原页打开弹窗 |
| 弹窗内容 | 标题、预订确认号、主驾驶人姓氏、一个查询按钮。确认号帮助由图标按需展开；底部仅用图标和“行程详情、费用明细、取消规则”说明能力，不承诺在线改订或续租 |
| PC / H5 | PC / Tablet 居中 Dialog；Mobile <768px 为 Bottom Sheet；共用业务状态。输入字号避免聚焦缩放，可滚动内容和安全区域均由共享弹层处理 |
| 列表下方入口 | 保留“没看到预订？查询并添加其他确认号”，打开同一个全局弹窗；成功追加并去重，关闭后保留列表筛选和原订单 |
| 订单详情 | 保持独立页面；服务器继续校验会话或账户归属；重新验证只能恢复刚验证的同一订单 |
| 关闭与加载 | 关闭不导航，恢复触发入口焦点；重新打开清空输入；提交中锁定关闭和重复提交；关闭入口检查后，其延迟结果不得把用户带离后来打开的页面或弹窗 |
| 兼容链接 | `/[lang]/manage-booking` 仍可直接访问；旧 `/[lang]/manage-booking/lookup` 转到首页并打开全局弹窗，无独立表单页。消费弹窗参数后清理地址，仅安全的同语言订单／结算路径可作为重新鉴权目标 |
| 授权与存储 | HttpOnly 会话 Cookie + 服务端逐笔授权，最长有效期 24 小时。订单、姓氏和确认号输入不写入浏览器持久化。列表不混入登录账户的其他订单，访客查询不隐式关联账户 |
| 本地调试 | 开发者工具清除包含 Cookie 的站点数据后刷新，入口重新要求鉴权；直接打开失权列表／详情会回到首页并弹出查单。产品不提供清除会话按钮或技术提示 |

## 程序验证

| 检查 | 结果 |
| --- | --- |
| 租车业务回归 | `npm run test:rental-business` 的 51 项场景通过；包含真实 Route Handler 的空会话、逐笔追加、重复去重、账户隔离、删除／撤销／过期 Cookie、鉴权恢复，以及五种语言的弹窗兼容链接与安全返回目标 |
| i18n | `npm run check:i18n` 通过；通过项目统一入口维护 EN / ZH / JA / ES / KO 的字段、错误、无障碍与三个能力标签 |
| 生产构建与产物 | 临时源码副本中的 `npm run build` 通过，并核对构建后的首页 canonical、订单路由 noindex / nofollow 与查单路由不预渲染订单。原目录构建先遇到 Google 字体 DNS 失败，取得正常构建权限后又在收集产物时两次遇到缺失文件；独立构建避免共享 `.next` 目录干扰，未覆盖原目录产物 |
| 类型与静态检查 | `npx tsc --noEmit` 及本次改动文件 ESLint 通过；生产构建仍有其他模块的既有 lint warnings |
| 本地预览 | `npm run preview` 复用同目录的健康服务；已提供 `http://localhost:4000/zh?bookingLookup=1` 预览入口；HTTP 健康不代表交互验收 |
| 浏览器 | 未运行自动化；以下项目均须由人点击确认，不能视为已验收 |
