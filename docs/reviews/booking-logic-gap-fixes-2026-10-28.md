# 预订主流程逻辑补漏与验证记录

日期：2026-10-28。基于 `main-booking-exception-coverage-audit-2026-10-28.md` 的审计结果。此次只修正业务判断、数据绑定、状态同步和恢复逻辑，沿用既有页面、弹层及操作形态；不据 IX 的功能范围新增商品或交易能力。

各类异常的当前触发条件、展示位置和人工进入步骤见 [异常页面、提示与恢复路径说明](../guides/exception-pages-and-recovery.md)。

后续已补充固定日期库存与特殊测试卡结果，最新范围和验证结果见[预订输入场景补全记录](local-booking-scenarios-2026-10-28.md)；本文保留首次补漏时的检查记录。

工作区另有并行的账户／访客查单页面调整。本记录只描述本次逻辑补漏；最终验收使用工作区最新入口，不将并行 UI 变化列为本次交付。

## 1. 404、恢复与异常的分流

| 场景 | 补齐后的结果 |
| --- | --- |
| 未知车辆 ID、报价车辆与路径车辆不符 | 真正的 Next 404；车辆查询不再回退第一辆车 |
| 报价尚在展示恢复保留期，但已过有效期 | 复用现有过期提示重新查价；服务端依旧禁止用过期报价下单 |
| 报价丢失、上下文不完整、报价不可用 | 回现有搜索／费率流程；安全返回只带公开行程和有效选择，不带旧报价 ID 或个人字段 |
| 订单或收银台缺少授权／会话过期 | 进入现有查单验证，成功后仅恢复同语言、同确认号的原页面 |
| 查单确认号或姓氏不匹配 | API 仍统一 `booking_not_found/404`，不泄露订单是否存在；表单保留输入 |
| 网络、超时、非 JSON、503 | 按临时服务异常处理；列表不假装为空，交易页不误转 404 |
| 429 | 显示稍后再试，不假装查无订单 |
| 未知 API 路径 | 保持 `invalid_request/404` |
| 未预期程序错误 | 继续进入既有异常兜底，不吞掉真实错误 |

## 2. 已补齐的逻辑

| 审计项 | 修正与范围 |
| --- | --- |
| F01 | 过期公共报价可短期保留用于展示恢复；原 3 分钟有效期不变。驾驶人页过期回既有费率过期提示，丢失上下文使用受限本地恢复路径。恢复快照超过 24 小时清理。 |
| F02–F04 | 区分资源访问失败、服务异常和请求过频；订单／收银台共享服务端读取分类；查单与列表保留真实失败语义。 |
| F05 | 查单恢复前台、跨标签页变更及定时同步；合并重叠刷新，避免操作前查询覆盖支付／取消结果；服务失败时停止付款，支付不确定时禁止重付，查到已确认支付自动恢复订单详情。仅服务端确认超时取消后才触发既有超时弹层。 |
| F06 | 详情页不为无地点身份的 Tokyo 等搜索补 LAX；解析保留仅有门店 ID 的行程；POI 与关联门店身份冲突不返回报价。另修正未知车辆查询回退第一辆车的问题。 |
| F07–F08 | 搜索使用门店 IANA 时区检查取还时刻，拒绝过去时间及不存在的夏令时时刻；创建预订再次核对取车时刻和当前报价可用性，拒绝创建立即过期的占位。 |
| F09 | 侧栏电话来自当前取车门店；电话缺失不套其他门店。复制收到实际成功结果后才显示成功。 |
| F10 | 共用现有预订／付款／退款状态映射；待付款列表金额取线上应付，已付取实际收款；取消提示按期限与权限显示，不把在租／完成一律写成已确认。 |
| F11 | 保留工作区已有取消弹层的试算 loading／error／ready、版本确认与失败核对；此次未另行改变弹层形态。 |
| F12（部分） | 新增付款处理中、未知和失败状态的五语言文案；已有保障名称改用翻译键。其余历史文案、在线核验／续租等能力宣传未在本次做 UI／内容重写。 |
| F13 | URL 保障枚举和设备数量统一校验，损坏 JSON 或非法选择回到有效默认值，避免显示 Basic 却提交非法保障。 |

## 4. 人工验收清单（全部待确认）

使用项目入口 `npm run preview` 复用或启动本地服务。下表每行均需在 PC 1440×900、Tablet 820×1180、H5 390×844 执行，并切换 `en / zh / ja / es / ko`。`{lang}` 替换为语言；`{code}`、`{rateId}` 取当前实际测试会话创建结果。支付仅用测试资料。

| 页面 URL | 操作步骤 | 预期结果 |
| --- | --- | --- |
| `http://localhost:4000/{lang}/rent?pickup=Tokyo&pickupStoreCode=KLDJ01` | 搜索、选车、选保障和设备，进入驾驶人、创建、支付、查看订单 | 门店、当地时间、保障设备与金额连续；订单侧栏电话对应东京 |
| `http://localhost:4000/{lang}/rent/toyota-rav4-suv?pickup=Tokyo` | 无地点 ID 打开 | 回搜索；不展示 LAX 的 Tokyo 费率 |
| `http://localhost:4000/{lang}/rent/does-not-exist` | 直接打开；另将有效报价 ID 搭配不同车型路径 | 404，不回退第一辆车 |
| `http://localhost:4000/{lang}/rent?pickup=LAX&pickupPoiId=poi-lax-airport&pickupDate=2020-01-01T10:00&returnDate=2020-01-02T10:00` | 查看结果、打开现有搜索编辑入口改为未来日期 | 原行程不返回可订库存，修正后恢复；不落通用异常 |
| `http://localhost:4000/{lang}/rent/toyota-rav4-suv?rateDetailsId={rateId}` | 选保障和设备，等 3 分钟后刷新／返回 | 既有过期提示可重新查询，保留可恢复选择，新报价 ID 不同 |
| `http://localhost:4000/{lang}/book/driver?rateDetailsId={rateId}` | 分别在有效期内和过期后打开；缺失 ID、服务重启后再试 | 有效继续；过期回既有提示；丢失上下文恢复搜索，不循环使用旧 ID |

## 5. 仍未闭合的边界

| 边界 | 当前结论 |
| --- | --- |
| FE 实时调价／政策变更、售罄、动态年龄费用、更多履约状态 | 需要真实 FE 协议和业务范围；此次只验证已有内部模型，不虚构状态或核心规则。 |
| 支付拒绝、3DS、回调验签／迟到／重复、真实退款与失败补偿 | 需要支付渠道与服务端对账；本地成功和退款模拟不能证明这些分支完成。 |
| 数据持久化、重启恢复、跨实例授权与幂等、真实通知 | 内部内存实现仍非生产能力；503 保护保留。 |
| JAF 商品、评价邀请、证件上传／审核、候补／拒单等 IX 扩展 | 不自动复制为 TrustGo 需求；需确认 FE 和实际产品范围。 |
| 历史能力宣传、H5 订单主操作布局、全局错误页历史文案、交易页索引边界 | 本次未做范围外 UI／内容／SEO 改造；应单独审查。 |
| 页面操作 | 上述 PC／Tablet／H5 五语言全部待人点击确认；未报告页面全量验收或与 IX 全功能等价。 |
