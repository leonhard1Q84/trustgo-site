## 结论与接入边界

原实现是浏览器内的交互演示，不能直接视为 FE 预订与支付闭环。问题集中在门店与行程丢失、前端决定订单状态、付款口径错误，以及未支付订单和不可取消订单也能全额退款。

本次将预订与授权移至服务端，补齐本地业务闭环及失败保护。生产 FE 接入、真实扣款、支付回调、真实退款及持久化订单库仍未接入。没有用本地成功状态替代这些外部能力。

## IX 中值得复用的实现思路

| 能力 | IX 证据 | TrustGo 采用方式 |
| --- | --- | --- |
| 搜索与费率规则分开 | `src/services/fleetedge.ts` 的可用性搜索、费率规则、库存校验 | 保留搜索 → 费率详情 → 创建预订顺序，费率上下文由服务端保存；不搬入另一套业务命名 |
| 创建预订幂等 | `createOrderReservation` 传入幂等标识，并检查 Held 状态和截止时间 | 服务端对同一提交复用结果，使用绝对支付期限 |
| 收银台恢复与核验 | `src/components/checkout/checkoutValidationCore.ts` 核对预订、金额、币种和支付期限 | 收银台从授权服务器记录恢复，不从 URL 或浏览器订单副本恢复金额 |
| 分开处理取消与退款 | `src/services/booking.ts` 的取消试算、取消订单、释放未付款预订 | 未支付取消不退款；已付款先试算再确认；退款状态单独记录 |
| 拦截终态操作 | `src/modules/booking-management/domain/orderStateMachine.ts` | 服务端和已有操作按钮共同使用状态守卫 |

IX 自身也保留了内部数据和待接入部分：`CheckoutPage.tsx` 的支付完成路径包含模拟确认，`services/payment.ts` 的 Stripe／PayPal SDK 仍是占位；内部取消规则使用 24 小时／20% 等示例数值。没有把这些当成 TrustGo 已确认的 FE 规则。TrustGo 内部取消试算沿用现有费率详情的免费取消窗口、晚取消 50%、临近取车 100% 演示规则，生产必须替换为 FE 返回的政策与试算结果。

## 未接入能力

| 能力 | 需要的外部条件 |
| --- | --- |
| 真实可用库存、年龄费用、异地还车、保障与税费 | FE 服务端接口、渠道配置与实际返回字段；不能由官网增加另一套定价规则 |
| 真实创建预订及释放占位 | FE 创建／查询／取消接口及权威状态，持久化与跨实例幂等 |
| 真正的支付失败、3DS、回调重试和支付结果未知对账 | 支付 provider 托管字段或托管收银台、服务端支付尝试、验签回调与查单 |
| 实际退款与退款失败补偿 | 支付／退款 provider 接口及可重试任务，不能按本地计时认定真实退款完成 |
| 邮件确认、证件上传与审核 | 通知与文件／预审服务及对应授权；当前不伪造发送或审核成功 |
| 在线修改／续租 | 当前版本不开放；调整行程须按允许的取消规则取消后重新预订；现有页面中超出该范围的静态宣传文案另行评审，不扩展业务能力 |
